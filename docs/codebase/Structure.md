# Structure — where do I put this?

Repo root: the `noteapi` package. Flat layout: three source files in `src/`, three test files in `test/`, config at the root. No monorepo, no workspaces.

## Directory map

```
noteapi/
├── src/                      # ALL service code (3 files, see below)
│   ├── index.ts              # entry point: env config + wiring only
│   ├── server.ts             # node:http server, router, request parsing
│   └── storage.ts            # Storage class — the ONLY persistence-touching module
├── test/                     # ALL tests (vitest; exempt from the storage-boundary lint rule)
│   ├── server.test.ts        # HTTP integration tests (real server, ephemeral port, temp DB)
│   ├── storage.test.ts       # Storage unit tests (temp dirs, direct DB/file inspection)
│   └── lint-guard.test.ts    # meta-test proving the storage-boundary lint rule works
├── docs/
│   └── codebase/             # this documentation (Architecture.md, Structure.md)
├── .github/
│   └── workflows/ci.yml      # CI: lint (--max-warnings 0), typecheck, test, build
├── .n8/                      # n8SDLC workflow state (config.yml, decisions.md, memory)
├── eslint.config.mjs         # flat config; carries the storage-boundary no-restricted-imports rule
├── tsconfig.json             # strict TS, NodeNext, includes src + test (typecheck/editor)
├── tsconfig.build.json       # build-only: rootDir src, emits to dist/
├── package.json              # ESM ("type": "module"); scripts: build/test/lint/typecheck/start
├── CLAUDE.md                 # project invariants (#7, #9) + n8SDLC drift protocol
├── README.md                 # service overview + build/test commands
├── SECURITY.md
├── dist/                     # GENERATED by `npm run build` — never edit, gitignored
├── node_modules/             # GENERATED — gitignored
└── data/                     # RUNTIME data (notes.db SQLite file) — gitignored, lint-ignored
```

Gitignored (`.gitignore`): `node_modules/`, `dist/`, `data/`, `*.log`. The same three directories are ESLint-ignored in `eslint.config.mjs`. Never commit or hand-edit anything under them; `data/notes.db` is user data created at runtime.

## Where things go

### A new endpoint
Add a branch in `async function handle(...)` in `src/server.ts`, matching on `segments` and `req.method` next to the existing `if (segments[0] === "notes")` branches. For a write endpoint, add a `parseX(raw: string)` validation function beside `parseCreate` in the same file, returning `{ ...fields } | { error: string }`. Respond only through `sendJson(res, status, payload)` (or bare `writeHead(204)`). Do not create a routes/ directory or per-route files — the router is a single function in `src/server.ts` until the codebase says otherwise.

### New storage logic
A new method on the `Storage` class in `src/storage.ts` — new SQL, new columns, any filesystem access. Follow the file's patterns: prepared statements on `this.db`, `NoteRow` + `rowToNote` for row conversion, JSON-in-TEXT for non-scalar columns, mutations returning `Promise.resolve(...)`, reads synchronous. `src/storage.ts` is the only file in `src/` allowed to import `node:fs`/`node:sqlite` (lint rule in `eslint.config.mjs`; guard test in `test/lint-guard.test.ts`).

### A new domain type
Export it from `src/storage.ts` alongside `Note` (types are exported from the module that owns them; `src/server.ts` imports `type { Storage }` and tests import `type Note` from `../src/storage.js`). There is no separate types/ or models/ file — do not create one for a single type.

### New wiring/config
Environment-variable reads and startup wiring go in `src/index.ts` only. Nothing else belongs there.

### Tests
All tests go in `test/*.test.ts` (vitest, run via `npm test` = `vitest run`). Pick the file by layer:
- HTTP behavior → `test/server.test.ts`: boot a real server on port 0 against a temp SQLite path (`mkdtemp` under `os.tmpdir()`), exercise it with global `fetch`, close servers in `afterEach`.
- Persistence behavior → `test/storage.test.ts`: temp store paths with not-yet-existing nested parents; assert on-disk state by opening the DB directly with `DatabaseSync` or reading files.
- Lint/tooling guarantees → `test/lint-guard.test.ts`: lint in-memory fixtures via the `ESLint` API.

`test/**` is exempt from the storage-boundary rule — tests may import `node:fs`/`node:sqlite` freely to prove storage behavior. Import source under test as `../src/<file>.js` (NodeNext ESM: `.js` extension on TS imports, everywhere).

### Lint rules
`eslint.config.mjs` (flat config, typescript-eslint recommended-type-checked). Warnings are errors (`npm run lint` = `eslint . --max-warnings 0`). Any rule suppression must carry a one-line rationale comment; changes to the storage-boundary rule must be mirrored in `test/lint-guard.test.ts`.

### TypeScript config
`tsconfig.json` is the source of truth (strict, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, NodeNext, includes `src` + `test`); `tsconfig.build.json` only narrows to `src` with `rootDir` for emitting `dist/`. Compiler-option changes go in `tsconfig.json`; touch `tsconfig.build.json` only for build-output concerns.

### CI
`.github/workflows/ci.yml`. It runs the four package scripts; keep any new check expressible as an npm script in `package.json` and invoked from there.

### Project-process files
`CLAUDE.md` lists the enforced invariants (#7 lint-warnings-are-errors, #9 storage boundary). Changing an invariant requires an `## Ad-hoc` entry in `.n8/decisions.md` per the protocol in `CLAUDE.md` — do not edit `.n8/` contents otherwise; it is n8SDLC workflow state, not application code.

## Commands

```bash
npm run build      # tsc -p tsconfig.build.json → dist/
npm test           # vitest run (all of test/)
npm run lint       # eslint . --max-warnings 0
npm run typecheck  # tsc --noEmit (src + test)
npm start          # node dist/index.js (NOTEAPI_FILE, PORT env vars)
```
